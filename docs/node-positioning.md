# Позиция ноды и внутренняя раскладка

Позиция в графе и геометрия содержимого принадлежат разным системам координат.

| Данные                               | Владелец                          | Когда меняются                                   |
| ------------------------------------ | --------------------------------- | ------------------------------------------------ |
| `node.x`, `node.y`                   | Приложение, внешний Konva `Group` | Drag, загрузка графа, автоматическое размещение  |
| Выделение и обработчики событий      | Приложение                        | Клик, tap, клавиатура                            |
| Локальные границы Flex/Cell/CellText | Библиотека                        | Изменение текста, стилей, размеров или структуры |
| Pan/zoom                             | Приложение, существующая камера   | Перемещение и масштабирование viewport           |

Внутренняя раскладка ноды считается от `(0, 0)` её группы. Перемещение внешнего `Group` переносит уже измеренное содержимое; нового HTML-измерения не требуется. Изменение описания может изменить высоту ноды и расположение её внутренних элементов, сохраняя её позицию в графе. Границы render-функций локальны относительно соответствующих ячеек.

`getLayout(id).absoluteX/absoluteY` относятся к корню соответствующего Layout, а не к пикселям экрана. Для группы без поворота и skew координата порта в графе равна позиции ноды плюс локальная координата порта. Например, нода `(500, 200)` и порт `(20, 80)` внутри её Layout дают точку `(520, 280)` в графе. Pan/zoom камеры переводит координаты графа в экранные и не участвует в HTML-измерении.

## Свободно перемещаемая нода

Внешний `Group` оборачивает корневой `Flex` с его собственной раскладкой:

```tsx
import { Group, Rect, Text } from 'react-konva';
import { Cell, CellText, Flex } from '@dzenlotus/react-konva-layout';

<Group
  x={node.x}
  y={node.y}
  draggable
  onClick={() => selectNode(node.id)}
  onDragEnd={(event) => updatePosition(node.id, event.target.position())}
>
  <Flex
    id={node.id}
    layoutRoot
    width={320}
    direction="column"
    padding={16}
    style={{ position: 'absolute', left: 0, top: 0 }}
  >
    <Cell width="100%" height="100%" style={{ position: 'absolute', left: 0, top: 0 }}>
      {(bounds) => (
        <Rect
          {...bounds}
          fill="white"
          stroke={selected ? '#789b58' : '#d9e0d2'}
          cornerRadius={12}
          listening
        />
      )}
    </Cell>
    <CellText text={node.description} fontSize={14}>
      {(textProps) => <Text {...textProps} />}
    </CellText>
  </Flex>
</Group>;
```

`node`, `selected`, `selectNode` и `updatePosition` — данные и действия приложения. Позиция `Group` хранится в системе координат его родителя: при родителе Layer под камерой Stage это координаты графа, без ручного умножения на zoom. Фон с `listening` даёт группе область попадания для клика и drag; декоративные рамки могут иметь `listening={false}`.

Во время drag Konva перемещает группу. `onDragEnd` сохраняет результат в вашем состоянии. Если приложению нужны текущие координаты для связей или других нод, оно может обрабатывать `onDragMove`. Вызов `invalidate` при простом перемещении не нужен. После изменения `node.description` пересчитывается внутренняя раскладка; явный пересчёт описан в [обновлении содержимого](content-updates.md).

Рабочий пример находится в [EmbeddedExample](../src/examples/EmbeddedExample.tsx): выбор, drag и hit-область находятся снаружи [ReferenceNode](../src/examples/ReferenceNode.tsx). Проверено перемещение `(300, 84) → (396, 132)`: локальное начало осталось `(0, 0)`, ревизия измерения не изменилась, HTML отсутствовал. Внешнее обновление текста дало локальное измерение 35 элементов.

## Ограничение текущего общего Layout

Один корневой `Flex` создаёт один движок измерения. Пример выше поэтому даёт отдельный движок каждой свободно перемещаемой ноде. Стресс-сцена на 1000 нод использует другой способ: один общий `Layout`, `layoutRoot` для каждой ноды и координаты через HTML `left/top`. Это обеспечивает общее измерение и шаблоны, но изменение таких координат проходит через механизм layout.

Результаты стресс-сцены не являются замером 1000 независимо перетаскиваемых внешних Group. Общее пакетное измерение с независимыми внешними Konva-группами пока не представлено публичным API. Нельзя помещать обычный Konva `Group` между `Layout` и измеряемыми `Flex/Cell`: дочернее дерево `Layout` сначала проходит через HTML-рендерер. Внешняя группа должна оборачивать корневой `Flex` или корневой `Layout`.
