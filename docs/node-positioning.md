# Свободное размещение, порядок и drag нод

У ноды есть внутренняя раскладка и позиция в графе. Библиотека измеряет первую; приложение хранит вторую вместе с порядком наложения и выделением.

| Данные                                 | Владелец                        | Когда меняются                                   |
| -------------------------------------- | ------------------------------- | ------------------------------------------------ |
| Позиция ноды `x/y` и порядок наложения | Приложение, `Layout.placements` | Drag, загрузка графа, автоматическое размещение  |
| Выделение и обработчики событий        | Приложение                      | Клик, tap, клавиатура                            |
| Локальные границы Flex/Cell/CellText   | Библиотека                      | Изменение текста, стилей, размеров или структуры |
| Pan/zoom                               | Приложение, существующая камера | Перемещение и масштабирование viewport           |

## Один Layout для всего графа

`Layout.placements` принимает массив `LayoutPlacement`. Каждый элемент находит независимый корень по его явному `id` и размещает его в собственной Konva-группе. У корня должен быть `layoutRoot`; его внутреннюю раскладку оставляют в начале координат. Порядок массива задаёт порядок от заднего плана к переднему.

Дерево измеряемых компонентов сохраняет стабильный порядок. Меняются только `placements`: перенос ноды и её поднятие поверх соседей не требуют перестановки HTML-элементов или нового измерения. Все ноды используют один движок измерения и общий кеш шаблонов.

Пример компонента для существующего `Stage/Layer`:

```tsx
import { useMemo, useState } from 'react';
import { Rect, Text } from 'react-konva';
import { Cell, CellText, Flex, Layout, type LayoutPlacement } from '@dzenlotus/react-konva-layout';

const nodes = [
  { id: 'node-a', text: 'Первый узел' },
  { id: 'node-b', text: 'Второй узел' },
];

export function FreeNodes() {
  const [positions, setPositions] = useState<Record<string, { x: number; y: number }>>({
    'node-a': { x: 80, y: 120 },
    'node-b': { x: 340, y: 70 },
  });
  const [order, setOrder] = useState(['node-b', 'node-a']);

  const placements = useMemo(
    () =>
      order.map<LayoutPlacement>((id) => ({
        id,
        ...positions[id],
        draggable: true,
        onDragStart() {
          setOrder((current) => [...current.filter((value) => value !== id), id]);
        },
        onDragEnd(event) {
          const position = event.currentTarget.position();
          setPositions((current) => ({ ...current, [id]: position }));
        },
      })),
    [order, positions],
  );

  const content = useMemo(
    () =>
      nodes.map((node) => (
        <Flex
          key={node.id}
          id={node.id}
          layoutRoot
          layoutTemplate="node-card-v1"
          width={300}
          padding={16}
          direction="column"
          style={{ position: 'absolute', left: 0, top: 0 }}
        >
          <Cell width="100%" height="100%" style={{ position: 'absolute', left: 0, top: 0 }}>
            {(bounds) => <Rect {...bounds} fill="white" cornerRadius={12} listening />}
          </Cell>
          <CellText text={node.text} fontSize={16}>
            {(textProps) => <Text {...textProps} />}
          </CellText>
        </Flex>
      )),
    [],
  );

  return (
    <Layout width={1200} height={800} placements={placements}>
      {content}
    </Layout>
  );
}
```

`width/height` общего `Layout` задают контекст HTML-измерения. Размер каждого абсолютного корня определяется его собственными ограничениями; координаты нод задаются только через `placements`. Не переносите позицию графа в CSS `left/top`: CSS участвует в измерении раскладки.

`content` в примере сохраняет ссылки при переносе и изменении порядка. В приложении с изменяемым содержимым его зависимости должны включать данные текста и стилей. Позиции, выделение и камера не должны заставлять заново создавать всё дерево из тысячи компонентов; вынесите ноду в `memo` или сохраняйте измеряемое дерево отдельно от состояния размещения.

## События и координаты

`LayoutPlacement` поддерживает `draggable`, `dragBoundFunc` и нативные обработчики Konva `onClick`, `onTap`, `onDragStart`, `onDragMove`, `onDragEnd`. `event.currentTarget` — внешняя группа размещения; `event.target` может быть вложенным текстом или фигурой. Для сохранения позиции используйте `event.currentTarget.position()`.

Во время drag группу перемещает Konva. Достаточно записать координаты в своё состояние по `onDragEnd`. Если связи должны следовать за нодой, используйте `onDragMove`. Фон с `listening` даёт группе область попадания; декоративные рамки можно рисовать с `listening={false}`. Клик и tap могут обновлять выделение в вашем store; библиотека не назначает стиль выделения.

`x/y` размещения заданы относительно группы общего `Layout`, до преобразования камеры. При стандартной сцене `Stage → Layer → Layout` это координаты графа. Умножать их на zoom вручную не нужно. Перемещение и изменение порядка сохраняют измеренную внутреннюю геометрию и не требуют `invalidate`.

Корень ноды внутри группы размещения начинается в `(0, 0)`. `getLayout(id).absoluteX/absoluteY` остаются координатами модели раскладки и не включают `placements` или камеру. Для порта используйте его смещение относительно корня ноды:

```ts
const root = layoutRef.current?.getLayout(nodeId);
const port = layoutRef.current?.getLayout(portId);

if (root && port) {
  const graphPoint = {
    x: nodePosition.x + port.absoluteX - root.absoluteX,
    y: nodePosition.y + port.absoluteY - root.absoluteY,
  };
}
```

Порядок массива `placements` также определяет попадание в перекрывающиеся ноды. Чтобы поднять выбранную ноду, переместите её запись в конец массива. Переставлять измеряемые `children` для этого не требуется.

Готовая сцена доступна по `?nodes=1`: произвольные позиции, перекрытие, выбор нод и drag. `?stress=1` сохраняет отдельную сцену замеров с фиксированной сеткой, поэтому её исторические показатели нельзя выдавать за замер свободного графа.

[Скриншот после drag](screenshots/free-nodes-drag.png) · [Проверка в production-сборке](free-nodes-verification.json).

`debug` показывает исходный измерительный HTML в его логических координатах. В версии 0.6.0 этот HTML не повторяет позиции и порядок `placements`: для свободного графа он служит инспектором внутренней раскладки, а рамку выбранной ноды приложение рисует отдельно в canvas. Размещения поддерживаются для независимых корней, которые являются границами отрисовки; вложенный `layoutRoot` внутри другого `layoutRoot` остаётся частью родительской ноды.

## Изменение содержимого

Изменение текста или стилей пересчитывает ближайшую независимую `layoutRoot`. Позиция ноды в `placements` сохраняется, а её высота и положения внутренних элементов могут измениться. Корень с абсолютным позиционированием и заданной шириной может менять высоту независимо от соседних нод.

Для изменений, которые не отражаются в свойствах, доступны `remeasure(id)` и `useLayout().invalidate(id)`. Эти методы нужны для обновления геометрии, а не для перемещения группы. Подробнее: [обновление содержимого и локальный relayout](content-updates.md).

Для одиночной ноды по-прежнему можно использовать внешний `<Group draggable>` вокруг самостоятельного `<Flex>`. У каждого такого корня будет свой движок измерения. Для большого графа используйте один общий `Layout` с `placements`. Обычные Konva `Group` нельзя вставлять внутрь измеряемого дерева между `Layout` и `Flex/Cell`: это дерево сначала рендерится в HTML.

## Восстановление камеры и детализация

Восстановите свои данные нод, массив размещений и `x/y/scaleX/scaleY` камеры до первого отображения сцены. Начальный zoom 0,05 или 0,1 не влияет на логические размеры: HTML измеряется в координатах раскладки, Stage отображает готовую геометрию в нужном масштабе.

Передайте тот же сохранённый zoom в собственные условия `Cell.renderWhen`, чтобы первый canvas-кадр использовал нужные fallback. При последующем зуме размеры ячеек сохраняются без HTML-релейаута. Формат внешнего store и способ сохранения выбирает приложение; библиотека не требует сериализации Konva-сцены. Подробнее: [выборочный LOD](cell-lod.md).
