# Свободное размещение, порядок и drag нод

У ноды есть внутренняя раскладка и позиция в графе. Библиотека измеряет первую; приложение хранит вторую вместе с порядком наложения и выделением.

| Данные                                 | Владелец                        | Когда меняются                                   |
| -------------------------------------- | ------------------------------- | ------------------------------------------------ |
| Позиция ноды `x/y` и порядок наложения | Приложение, `Layout.placements` | Drag, загрузка графа, автоматическое размещение  |
| Выделение и обработчики событий        | Приложение                      | Клик, tap, клавиатура                            |
| Локальные границы Flex/Cell/CellText   | Библиотека                      | Изменение текста, стилей, размеров или структуры |
| Pan/zoom                               | Приложение, существующая камера | Перемещение и масштабирование viewport           |

## Один Layout для всего графа

`Layout.placements` принимает массив `LayoutPlacement`. Каждый элемент находит независимый корень по его явному `id` и размещает существующую корневую Konva-группу. Дополнительная внешняя группа не создаётся; эта же группа кешируется и получает native события. У корня должен быть `layoutRoot`; его внутреннюю раскладку оставляют в начале координат. Порядок массива задаёт порядок от заднего плана к переднему.

Дерево измеряемых компонентов сохраняет стабильный порядок. Меняются только `placements`: перенос ноды и её поднятие поверх соседей не требуют перестановки HTML-элементов или нового измерения. Все ноды используют один движок измерения и общий кеш шаблонов.

Пример компонента для существующего `Stage/Layer`:

```tsx
import { useMemo, useState } from 'react';
import { Rect, Text } from 'react-konva';
import { Cell, CellText, Flex, Layout, type LayoutPlacement } from '@dzenlotus/react-konva-layout';

const nodes = [
  { id: 'node-a', text: 'Первый узел' },
  { id: 'node-b', text: 'Второй узел' },
];

export function FreeNodes() {
  const [positions, setPositions] = useState<Record<string, { x: number; y: number }>>({
    'node-a': { x: 80, y: 120 },
    'node-b': { x: 340, y: 70 },
  });
  const [order, setOrder] = useState(['node-b', 'node-a']);

  const placements = useMemo(
    () =>
      order.map<LayoutPlacement>((id) => ({
        id,
        ...positions[id],
        draggable: true,
        onDragEnd(event) {
          const position = event.currentTarget.position();
          setPositions((current) => ({ ...current, [id]: position }));
          setOrder((current) => [...current.filter((value) => value !== id), id]);
        },
      })),
    [order, positions],
  );

  const content = useMemo(
    () =>
      nodes.map((node) => (
        <Flex
          key={node.id}
          id={node.id}
          layoutRoot
          layoutTemplate="node-card-v1"
          width={300}
          padding={16}
          direction="column"
          style={{ position: 'absolute', left: 0, top: 0 }}
        >
          <Cell width="100%" height="100%" style={{ position: 'absolute', left: 0, top: 0 }}>
            {(bounds) => <Rect {...bounds} fill="white" cornerRadius={12} listening />}
          </Cell>
          <CellText text={node.text} fontSize={16}>
            {(textProps) => <Text {...textProps} />}
          </CellText>
        </Flex>
      )),
    [],
  );

  return (
    <Layout width={1200} height={800} placements={placements}>
      {content}
    </Layout>
  );
}
```

`width/height` общего `Layout` задают контекст HTML-измерения. Размер каждого абсолютного корня определяется его собственными ограничениями; координаты нод задаются только через `placements`. Не переносите позицию графа в CSS `left/top`: CSS участвует в измерении раскладки.

`content` в примере сохраняет ссылки при переносе и изменении порядка. В приложении с изменяемым содержимым его зависимости должны включать данные текста и стилей. Позиции, выделение и камера не должны заставлять заново создавать всё дерево из тысячи компонентов; вынесите ноду в `memo` или сохраняйте измеряемое дерево отдельно от состояния размещения.

## События и координаты

`LayoutPlacement` поддерживает `draggable`, `dragBoundFunc` и нативные обработчики Konva `onClick`, `onTap`, `onMouseDown`, `onTouchStart`, `onDragStart`, `onDragMove`, `onDragEnd`. `event.currentTarget` — корневая группа ноды: её `id()` и атрибут `layoutRootId` совпадают с `placement.id`. `event.target` может быть вложенным текстом или фигурой. Для сохранения позиции используйте `event.currentTarget.position()`.

Во время drag группу перемещает Konva. Достаточно записать координаты в своё состояние по `onDragEnd`. Если связи должны следовать за нодой, используйте `onDragMove`. Интерактивное размещение получает область попадания по полным измеренным границам корня через hit-only Shape; она не рисует фон в scene canvas. Декоративные рамки можно рисовать с `listening={false}`. Клик и tap могут обновлять выделение в вашем store; библиотека не назначает стиль выделения.

`x/y` размещения заданы относительно группы общего `Layout`, до преобразования камеры. При стандартной сцене `Stage → Layer → Layout` это координаты графа. Умножать их на zoom вручную не нужно. Перемещение и изменение порядка сохраняют измеренную внутреннюю геометрию и не требуют `invalidate`.

Содержимое корневой группы начинается в `(0, 0)`. `getLayout(id).absoluteX/absoluteY` остаются координатами модели раскладки и не включают `placements` или камеру. Для порта используйте его смещение относительно корня ноды:

```ts
const root = layoutRef.current?.getLayout(nodeId);
const port = layoutRef.current?.getLayout(portId);

if (root && port) {
  const graphPoint = {
    x: nodePosition.x + port.absoluteX - root.absoluteX,
    y: nodePosition.y + port.absoluteY - root.absoluteY,
  };
}
```

Порядок массива `placements` также определяет попадание в перекрывающиеся ноды. Чтобы поднять выбранную ноду, переместите её запись в конец массива. Переставлять измеряемые `children` для этого не требуется.

Готовая сцена доступна по `?nodes=1`: произвольные позиции, перекрытие, выбор нод и drag. `?stress=1` сохраняет отдельную сцену замеров с фиксированной сеткой, поэтому её исторические показатели нельзя выдавать за замер свободного графа.

[Скриншот после drag](screenshots/free-nodes-drag.png) · [Проверка в production-сборке](free-nodes-verification.json).

`debug` показывает исходный измерительный HTML в его логических координатах. В версии 0.6.0 этот HTML не повторяет позиции и порядок `placements`: для свободного графа он служит инспектором внутренней раскладки, а рамку выбранной ноды приложение рисует отдельно в canvas. Размещения поддерживаются для независимых корней, которые являются границами отрисовки; вложенный `layoutRoot` внутри другого `layoutRoot` остаётся частью родительской ноды.

## Drag на отдельном слое

Простой пример выше использует один существующий Layer. При большом числе видимых нод можно повторить схему из [`FreeNodesExample.tsx`](../src/examples/FreeNodesExample.tsx): приложение создаёт второй interaction Layer с теми же преобразованиями камеры, а во время drag рисует на нём только перетаскиваемую ноду и выделение.

1. В `onDragStart` сохраните native группу и её исходного родителя, обновите выделение. После React commit перенесите группу в interaction Layer, сохранив `getAbsolutePosition()` через `absolutePosition(...)`.
2. В `onDragMove` перемещайте связанные native фигуры или обновляйте только нужные подписки. Координаты всех нод не нужно записывать в React state на каждом событии.
3. В `onDragEnd` сначала верните группу в исходного React-родителя с сохранением абсолютной позиции. Затем запишите её локальную `position()` и перенесите запись в конец массива `placements`. Interaction Layer обеспечивает передний план во время drag; порядок массива фиксируется при отпускании.

Завершайте активный drag до изменения камеры, размеров viewport, содержимого, расстановки или порядка: React должен обновлять siblings в своей native иерархии. Демо также наблюдает внешние изменения Stage, поэтому native pan/zoom и resize завершают жест до culling. На размонтировании временно перенесённая группа возвращается в исходного родителя. При разных преобразованиях Layer нужно преобразовывать координаты выделения и связей; демо использует одинаковую камеру на уровне Stage.

Сам `Layout` не создаёт слоёв, не переносит группу между ними и не управляет камерой. Подключение второго слоя — решение приложения; интерфейс `placements` остаётся тем же.

## Камера и hit-map

В демо текущая камера хранится в ref и применяется к native Stage. Число zoom обновляется через DOM ref; React-состояние меняется, когда меняются условия отрисовки выбранных ячеек. Это исключает обновление всего приложения на каждом кадре pan/zoom. Не передавайте параллельно устаревшие `x/y/scale` в JSX Stage: React commit может перезаписать текущую native камеру.

[`useCameraHitGraph.ts`](../src/examples/useCameraHitGraph.ts) временно выключает `listening` основного слоя при изменении камеры, чтобы не рисовать hit-map на каждом движении. Через 120 мс покоя восстанавливается прежнее значение и планируется draw. Capture-обработчики `pointerdown`, `mousedown` и `touchstart` восстанавливают hit-map синхронно до Konva picking, если пользователь нажал раньше. Сцена продолжает рисоваться с тем же разрешением; LOD и размеры библиотека при этом не меняет. Первое нажатие после движения может включать стоимость восстановления hit-map, поэтому её нужно оценивать отдельно от FPS непрерывного жеста.

## Сравнение со свободной сценой

Откройте `?nodes=1&benchmark=1`: Stage фиксируется на 1400 × 760. В консоли можно выбрать одинаковое содержимое со свободными координатами или сеткой:

```js
const api = window.freeNodes;
const view = { x: 36, y: 60, scale: 0.03 };
await api.benchmark.mount({ arrangement: 'free', view }); // либо 'grid'
await api.benchmark.interact({ kind: 'drag', view, warmupMs: 1000, durationMs: 5000 });
await api.benchmark.interact({
  kind: 'pan',
  view,
  panAmplitude: { x: 100, y: 15 },
  warmupMs: 1000,
  durationMs: 5000,
});
await api.benchmark.interact({
  kind: 'zoom',
  view,
  zoomRange: { min: 0.025, max: 0.035 },
  warmupMs: 1000,
  durationMs: 5000,
});
```

Для независимых сравнений вызывайте `mount` заново перед каждым жестом. Эмуляция CPU и DPR задаётся средствами браузера. API возвращает исходные интервалы кадров, длительности draw по слоям и проверки отсутствия HTML-измерений. Замер drag начинает native жест программно и затем отправляет mousemove/mouseup; попадание по маленькой ноде отдельно в этот FPS не входит. RAF и завершённый `Layer.draw` характеризуют JavaScript-отрисовку, а не физическое представление кадра GPU. Протокол и результаты: [стресс-тест свободной сцены и сравнение с сеткой](free-scene-stress.md). Старый `?stress=1` остаётся отдельной статичной сеткой без drag.

## Изменение содержимого

Изменение текста или стилей пересчитывает ближайшую независимую `layoutRoot`. Позиция ноды в `placements` сохраняется, а её высота и положения внутренних элементов могут измениться. Корень с абсолютным позиционированием и заданной шириной может менять высоту независимо от соседних нод.

Для изменений, которые не отражаются в свойствах, доступны `remeasure(id)` и `useLayout().invalidate(id)`. Эти методы нужны для обновления геометрии, а не для перемещения группы. Подробнее: [обновление содержимого и локальный relayout](content-updates.md).

Для одиночной ноды по-прежнему можно использовать внешний `<Group draggable>` вокруг самостоятельного `<Flex>`. У каждого такого корня будет свой движок измерения. Для большого графа используйте один общий `Layout` с `placements`. Обычные Konva `Group` нельзя вставлять внутрь измеряемого дерева между `Layout` и `Flex/Cell`: это дерево сначала рендерится в HTML.

## Восстановление камеры и детализация

Восстановите свои данные нод, массив размещений и `x/y/scaleX/scaleY` камеры до первого отображения сцены. Начальный zoom 0,05 или 0,1 не влияет на логические размеры: HTML измеряется в координатах раскладки, Stage отображает готовую геометрию в нужном масштабе.

Передайте тот же сохранённый zoom в собственные условия `Cell.renderWhen`, чтобы первый canvas-кадр использовал нужные fallback. При последующем зуме размеры ячеек сохраняются без HTML-релейаута. Формат внешнего store и способ сохранения выбирает приложение; библиотека не требует сериализации Konva-сцены. Подробнее: [выборочный LOD](cell-lod.md).
