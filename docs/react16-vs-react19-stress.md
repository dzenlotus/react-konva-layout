# React 16 и React 19: свободная сцена из 1000 нод

Свежая парная матрица сравнивает два полных стека на одной сцене: **React 16.14.0 / React Konva 16.13.0-6 / Konva 8.4.3** и **React 19.3.1 / React Konva 19.3.2 / Konva 10.9.0**. Разницу нельзя приписать одному React. Во всех таблицах порядок значений **React 16 → React 19**; каждое значение — медиана трёх повторов; диапазоны min–max, максимумы и меньший n для слоёв указаны явно. Изменение в процентах рассчитано как `(19 / 16 − 1) × 100`.

При CPU ×6 rendered FPS drag/pan/zoom составили 48.4 → 54.1 / 13.5 → 21.7 / 15.2 → 13.7. Медианный первый draw при ×6: 2635.9 → 2739.9 мс на 100% и 11739.7 → 7441.8 мс на 3%. Порядок в каждой паре: React 16 → React 19; это наблюдения данной серии.

При CPU ×6 React 19 zoom дал три результата **18.19 / 0.70 / 13.73 FPS**. В худшем прогоне 5 draw-интервалов за 7170.5 мс; пауза rAF **5.61 с**, один Layer.draw **5.54 с** внутри окна. Этот прогон полностью сохранён; медиана 13.7 FPS не подтверждает стабильную скорость zoom.

Отпускание drag выполняется за пределами окна FPS. Медианный post-run хвост при CPU ×1/×4/×6: 268.5 → 279.8 / 754.9 → 2684.7 / 944.1 → 1285.0 мс (16 → 19 в каждой паре). Высокий FPS движения следует читать вместе с этими задержками.

## Начало и завершение native drag

`startCall` — синхронный `startDrag()` вместе с обработчиками приложения; `releaseCall` — синхронный dispatch mouseup и остановка drag. Первый draw после начала/отпускания относится к **любому** слою Stage и не доказывает готовность окончательного кадра. `releaseCall` не включает отложенный commit React 19. Поэтому дополнительно приведён `postRunTail`: от конца измеряемого окна до чтения сохранённых координат и порядка после возврата helper. Он включает release, два rAF и проверку состояния внутри helper; postRun timestamp снимается после чтения persisted-результата. Это proxy хвоста, а не физическая задержка ввода/показа; сохранённые координаты и передний порядок проверяются отдельно.

## Методика и проверка

Исходный commit: `14f556a17a3d5289f46112ac08ce061393091016`. Перед заморозкой общий пример получил `unstable_batchedUpdates` вокруг native onDragStart/onDragEnd в **обоих** стеках; ядро SDK этим изменением не затронуто. Диагностика до исправления измерила синхронный native `releaseCall` React 16 в 266.1 мс; один контроль после исправления дал 152.3 мс. Эти двухсекундные n=1 наблюдения с другой целью drag (`free-node-0000`) не входят в матрицу и не являются статистическим результатом. [Диагностические записи](benchmarks/react16-vs-react19/preflight.json).

- Одна полная 35-элементная конструкция ноды, 1000 свободно размещённых копий, 35 001 элемент модели. Seeds, порядок, JPEG, камера и исходники общие. На 3% выбраны все 1000 корней; Cell LOD приложения одинаковый.
- Apple M5, 24 GiB RAM, 10 логических CPU; HeadlessChrome 155.0.0.0, окно 1600×1000 CSS px, DPR 2, Stage 1400×760. CPU ×1/×4/×6 — DevTools slowdown main thread этого компьютера. Он не эмулирует слабый GPU, память или другое устройство. UA сообщает Intel Mac OS X; чип Apple M5 проверен отдельно через sysctl. Полный UA и идентичность сборок сохранены в raw protocol/parity ниже.
- По три повтора каждой пары CPU/runtime/scenario: 90 строк, 54 взаимодействия. Порядок runtime контрсбалансирован по CPU и повтору; внутри runtime mount100 и mount3, затем три жеста с вращением порядка. Каждый жест получает свежий mount; автоматическая исходная сцена и assets готовы до старта измерения.
- Обзорная камера `(x=36, y=60, scale=0.03)`, pan amplitude `(100, 15)` CSS px; zoom 0.025–0.035 с якорем в центре Stage. Native drag одной цели `free-node-0168` в обоих стеках: синусоидальное движение ±90/50 CSS px через DOM mousemove/mouseup. Исходная позиция `(6277.7379773091525, 2053.0010906700045)` держит весь путь на экране при 3%; программный startDrag исключает hit-testing крошечной цели из этой метрики.
- Запрошены 1000 мс прогрева и 5000 мс измерения. Все границы и интервалы используют единственный `performance.now()`; сохранены точные timestamp и draw-флаг каждого интервала. Ни один интервал не отрезан, не заменён и не сглажен. Длительность равна и `end − start`, и сумме интервалов.
- Валидатор проверил nearest-rank p50/p95/p99, FPS, draw flags/counts/layers, DPR 2, геометрию Stage и полный состав модели. В движении: 0 layout passes, 0 BCR измерительного дерева, 0 прикреплений измерительного HTML; revision, mode и DPR стабильны. Во всех 18 drag: started=ended=1, moved>0, stopped=true, ошибка ≤0.01; координаты после возврата и front=true сохранены.
- Pan/zoom приостанавливает hit-map. Восстановление после покоя/первого нажатия не входит в устойчивый FPS; native Layer.draw не равен GPU presentation. Три повтора дают медианы и диапазон наблюдений, без доверительного интервала и без вывода о других устройствах.
- В отдельном native parity spot-check при 3% по целочисленным размерам native canvas-кешей получено ровно 6 000 000 байт в обоих стеках, по 1000 кешированных корней. Это объём растровых данных после подготовки, не пик всей матрицы и не измерение RSS/VRAM. SDK-снимок React 19 был устаревшим (3 000 000), а React 16 считал дробные размеры обёртки (6 365 250). Поле `reportedMaxCacheBytes` в сводке сохраняет сообщённую SDK оценку; оно не используется для сравнения физической памяти.
- Предыдущие замеры со смешанными часами и их скорректированные окна в это сравнение не включены. Это новая матрица двух свежих сборок на одинаковом helper.

## Наблюдение по коду

Drop обновляет nodes/order и создаёт 1000 новых объектов placements. Это вызывает повторные render корней и обновление native event handlers; существующие native группы и кеши сохраняются. Путь подтверждён в [FreeNodesExample](../src/examples/FreeSceneExample.tsx), [PlacedRoot](../src/lib/rendering/PlacedRoot.tsx) и [SceneIsland](../src/lib/rendering/SceneIsland.tsx). Без количественного профиля нельзя назвать его доказанной причиной пауз около 4.4 с. Konva 8 рисует hit cache при Node.cache(), Konva 10 подготавливает эту часть отложенно: это качественное различие работы версий, не измеренная доля задержки.

## Воспроизведение

Production-сборки из измеренного исходного commit; preview запускается отдельным терминалом для каждого стека:

```sh
npm ci --ignore-scripts
npm run build
npm run preview -- --host 127.0.0.1 --port 4183 --strictPort
```

```sh
npm run build:react16-stress
npx vite preview --config vite.react16-stress.config.ts --host 127.0.0.1 --port 4184 --strictPort
```

Открыть `http://127.0.0.1:4183/?nodes=1&benchmark=1` и аналогичный URL на 4184. Установить CSS viewport 1600×1000, DPR 2, активную вкладку и DevTools CPU ×1/×4/×6. Дождаться готовой исходной сцены; JPEG decode и fonts.ready также ожидаются в mount helper. В консоли каждой страницы:

```js
while (!window.freeNodes?.stats().complete)
  await new Promise((resolve) => requestAnimationFrame(resolve));
const api = window.freeNodes;
const view = { x: 36, y: 60, scale: 0.03 };
const first100 = await api.benchmark.mount({
  arrangement: 'free',
  view: { x: 0, y: 0, scale: 1 },
});
const first3 = await api.benchmark.mount({ arrangement: 'free', view });
// Перед КАЖДЫМ drag/pan/zoom — новый mount; здесь показан drag.
const mount = await api.benchmark.mount({ arrangement: 'free', view });
const result = await api.benchmark.interact({
  kind: 'drag',
  targetId: 'free-node-0168',
  view,
  panAmplitude: { x: 100, y: 15 },
  zoomRange: { min: 0.025, max: 0.035 },
  warmupMs: 1000,
  durationMs: 5000,
});
const persisted = {
  node: api.nodes().find((node) => node.id === 'free-node-0168'),
  front: api.order().at(-1) === 'free-node-0168',
};
const postRunAtMs = performance.now();
const postRunTailMs = postRunAtMs - result.measurementEndedAtMs;
console.log({ first100, first3, mount, result, persisted, postRunAtMs, postRunTailMs });
```

Повторить с kind `pan` и `zoom` по три раза для каждого CPU/стека, сохраняя порядок runtime/scenario и метаданные из raw protocol. Это браузерное повторение; следующий Python шаг только проверяет и агрегирует сохранённые файлы.
