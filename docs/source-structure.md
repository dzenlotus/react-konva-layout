# Карта исходников

Библиотека находится в `src/lib`; демонстрационные приложения используют её публичный API. Вход для потребителя — [`src/lib/index.ts`](../src/lib/index.ts). Он экспортирует компоненты раскладки и опциональные hooks управления существующей камерой, без создания Stage или импорта демо.

## Библиотека

| `measurement/MeasurementPass.ts`, `MeasurementReader.ts`            | Временное подключение HTML и чтение геометрии браузера.                                          |

## Приложения и замеры

- `main.tsx` выбирает пример и загружает его отдельно. `examples/EmbeddedExample.tsx` показывает интеграцию; приложение создаёт существующие Stage/Layer и подключает к ним библиотечные hooks камеры. `DemoCanvas.tsx` и оставшиеся вспомогательные функции примера не входят в библиотечный entrypoint.
- `examples/ReferenceCard.tsx` — оформленная карточка из `Flex/Cell/CellText`. `DesignedStressScene.tsx` размещает 1000 таких карточек с одной декодированной фотографией.
- `examples/FreeSceneExample.tsx` и `freeSceneModel.ts` — свободная сцена из 1000 карточек: внешний state позиций и порядка, выделение, drag и камера. `?scene=1` использует один общий `Layout` с `placements`. Приложение создаёт основной и interaction Layer; на время drag корневая группа переносится во второй слой и возвращается до обновления React-состояния. Native Stage и ref камеры обновляются без React-рендера на каждом кадре; React получает изменения условий LOD ячеек.
- `examples/useCameraHitGraph.ts` — приложение приостанавливает hit-map основного слоя на время изменения камеры. Исходный `listening` восстанавливается через 120 мс покоя либо синхронно в capture-обработчике перед новым pointer/mouse/touch picking. Содержимое scene canvas и разрешение Layer сохраняются.
- `examples/text-editor/` — собственный редактор демо: textarea, ввод, сохранение, отмена и CSS-позиционирование. Библиотечные компоненты только измеряют текст и не назначают поведение редактирования.
- `App.tsx` собирает playground. В `playground/` находятся сцены, настройки, HTML-инспектор, дерево и копирование результата.
- `StressApp.tsx` собирает стресс-интерфейс. `stress/useStressBenchmark.ts` управляет сценой и операциями `window.layoutStress`; `types.ts` описывает их контракт, `StressResults.tsx` выводит результаты.
- `stress/completedDraw.ts` проверяет готовность геометрии, изображения и качества кеша перед завершением замера. `benchmarks/camera.ts` отдельно считает RAF и завершённые `Layer.draw`; прогрев и загрузка фотографии исключены из соответствующих таймеров.
- `benchmarks/freeMount.ts` проверяет первый завершённый кадр свободной сцены, камеру, геометрию, содержимое ячеек и плотность кешей. `benchmarks/freeScene.ts` измеряет native drag или обычный путь камеры приложения, RAF и завершённые draw каждого слоя. В `?scene=1&benchmark=1` API `window.freeScene.benchmark` сравнивает свободное и сеточное размещение на одном Stage 1400 × 760. Протокол и результаты: [стресс-тест свободной сцены](free-scene-stress.md).
- `packages/react16/stress` запускает тот же `FreeSceneExample` на React 16.14.0; `vite.react16-stress.config.ts` изолирует React/React DOM/react-konva/Konva старого стека. `scripts/summarize-react16-comparison.py` проверяет 90 записей и собирает [парное сравнение](react16-vs-react19-stress.md) из raw JSON.

## Инварианты при изменениях

- После измерения HTML отсоединён от документа; debug подключает измерительный DOM только на время использования. Дополнительным DOM интерфейса приложения владеет само приложение.
- Изменение `text`, стилей, структуры и ограничений размера планирует измерение автоматически. Обновление содержимого независимой `layoutRoot` пересчитывает её ветвь, сохраняя модель, группы и кеши соседей. Если безопасное локальное измерение невозможно, используется полное.
- `invalidate(id)` планирует пересчёт с доступными шаблонами; `remeasure(id)` сбрасывает кеши измерения перед пересчётом. Запросы объединяются через RAF. Подробнее: [обновление содержимого](content-updates.md).
- Внешняя камера остаётся у приложения. Pan/zoom обновляет видимость без HTML layout; библиотека сохраняет pixel ratio существующего Layer. `usePanZoom` и `useLayoutDrag` используют один контроллер: drag перемещает камеру сцены, а ограничения проверяются и при zoom. Подробнее: [управление камерой](camera-controls.md).
- Позиции и порядок `placements` относятся к canvas. Измеряемые `children` сохраняют свой порядок; перенос и поднятие карточки не пересчитывают геометрию и не перестраивают её растровый кеш.
- Размещённый корень — одна существующая кешируемая Konva-группа с `id = placement.id`, без внешней обёртки. Полная область попадания интерактивного корня рисуется только в hit canvas; дочерние координаты и модель остаются локальными.
- Автоматическая плотность кеша учитывает Layer и трансформации, меняется по степеням двойки с гистерезисом и минимумом `1/64`. Hit-кеш использует `min(1, scenePixelRatio)`; бюджет 32 MiB учитывает дополнительную filter-поверхность только при настроенных фильтрах. При нехватке бюджета карточка рисуется напрямую. Pixel ratio самого Layer не уменьшается.
- `onRenderStats` отправляет изменившиеся метрики, а новый callback получает текущий снимок. Подсчёт native групп и фигур переиспользуется при чистом движении камеры; без подписчика сбор метрик не планируется.
- Временный native перенос в другой слой — ответственность приложения. До изменения камеры, viewport или содержимого демо завершает drag и возвращает группу в React-родителя, чтобы culling и обновление siblings работали в исходной иерархии.
- `Cell`/`CellText.renderWhen` и `fallback` меняют только canvas-содержимое; HTML и сохранённая геометрия остаются полными. Первый проход измеряет обычную раскладку даже при начальном zoom 0,05. В библиотеке нет порогов LOD и автоматической замены целой карточки. Подробнее: [выборочный LOD](cell-lod.md).
- Публичные компоненты, ref/context и методы `window.layoutStress` сохраняют существующий контракт.

## Проверка рефакторинга до версии 0.5.0

Следующие результаты зафиксированы до перехода на выборочный LOD и описывают прежний вариант сцены.

TypeScript, production-сборки приложения и библиотеки, Prettier и независимый обзор пройдены. Новые тесты и зависимости не добавлялись; поведение проверено в браузере.

В стресс-сцене подтверждены 1000 карточек, 35 001 элемент модели, 1035 чтений геометрии, 999 попаданий в шаблон и HTML 0 в покое. При DPR 2 три прогона pan и три zoom дали 60 FPS; это контроль сохранения поведения на текущей машине, без заявления об ускорении относительно предыдущих замеров.

Локальная правка прочитала 35 элементов, сохранив ссылки модели, Konva-группу и растровый кеш соседней карточки. Плотность кеша составила 2 при zoom 1 и 4 при zoom 1,6. В development StrictMode проверены IME, сохранение через blur, отмена Escape и сохранность черновика при внешних rotation/skew.
