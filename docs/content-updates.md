# Обновление содержимого

`Flex`, `Cell` и `CellText` измеряют раскладку и передают границы в canvas. Ввод текста, выбор элементов, сетевые запросы и другие действия организует приложение. У `CellText` нет встроенного режима редактирования.

## Управляемые данные

Передавайте актуальный текст и его стили через свойства `CellText`:

```tsx
import { Text } from 'react-konva';
import { CellText, Flex } from '@dzenlotus/react-konva-layout';

function GraphNode({ description }: { description: string }) {
  return (
    <Flex
      id="node-1"
      layoutRoot
      width={320}
      direction="column"
      padding={16}
      style={{ position: 'absolute', left: 40, top: 60 }}
    >
      <CellText
        id="node-1-description"
        text={description}
        width="100%"
        fontFamily="Arial"
        fontSize={14}
        lineHeight={1.5}
        wrap="word"
      >
        {(textProps) => <Text {...textProps} />}
      </CellText>
    </Flex>
  );
}
```

При изменении `description` React обновляет временное HTML-дерево, а движок автоматически планирует новое измерение. Это одинаково работает для значения из `useState`, внешнего store, собственного input или ответа API. Ручной `invalidate` для обычного обновления свойств не нужен. Так же обрабатываются ограничения размера, типографика и `style`.

Свойства из render-функции включают локальные границы и измеренную типографику: передавайте их целиком в `<Text {...textProps} />`. Если задать другой `text` или шрифт только у Konva `Text`, измерительный HTML об этом не узнает. Сначала обновите источник данных `CellText`; один вызов `invalidate` не синхронизирует canvas с моделью.

У обычного `Cell` размер определяется его CSS-ограничениями и вложенной раскладкой. Для произвольной фигуры или изображения приложение задаёт нужные `width`, `height` или ограничения размера. Render-функция рисует по измеренным границам; библиотека не извлекает intrinsic-размеры из произвольного Konva-дерева.

## Локальное измерение

`layoutRoot` помечает границу независимой ноды. Обновление её содержимого измеряет ближайшую такую границу целиком, поскольку перенос текста может изменить высоту и расположение остальных элементов внутри ноды. Несколько запросов до следующего RAF объединяются; вложенные запросы не измеряют одну ветвь повторно.

В примере выше нода имеет явную ширину и абсолютные `left/top`, поэтому новая высота не сдвигает соседние ноды. Геометрия неизменённых соседей сохраняет ссылки, что позволяет сохранить их Konva-группы и растровые кеши.

Локальное измерение используется, когда оно безопасно. Изменение ограничений самой `layoutRoot`, отсутствие явной ширины, трансформирующие CSS-правила или зависимость от соседних CSS-селекторов могут потребовать полного измерения. Если нода находится в обычном потоке и изменила размер, пересчитывается общий layout, чтобы соседи получили правильные координаты. Обычный внешний pan/zoom HTML-измерение не запускает.

## Явный запрос пересчёта

Корневой `Layout` или корневой `Flex` предоставляет `ref` типа `LayoutHandle`. Вложенный `Flex` участвует в общем измерении; его `ref` не создаёт отдельный контроллер.

```tsx
import { useRef } from 'react';
import { Layout, type LayoutHandle } from '@dzenlotus/react-konva-layout';

const layoutRef = useRef<LayoutHandle>(null);

<Layout ref={layoutRef} width={4000} height={3000}>
  <GraphNode description={description} />
</Layout>;

// Запланировать локальное измерение с доступными кешами геометрии.
layoutRef.current?.invalidate('node-1-description');

// Прочитать заново, сбросив кеши шаблонов и вычисленных стилей.
layoutRef.current?.remeasure('node-1-description');

// Перечитать всё дерево, например после внешней смены CSS-контекста.
layoutRef.current?.remeasure();
```

Оба метода принимают `id` элемента и выбирают ближайшую `layoutRoot`; условия безопасности по-прежнему действуют. Если границы или указанного `id` нет, выполняется полное измерение. `invalidate()` без аргумента тоже сбрасывает кеши измерения и планирует полный проход.

`invalidate(id)` может повторно использовать шаблон геометрии при неизменной сигнатуре. `remeasure(id)` перед запросом очищает общие кеши шаблонов и вычисленных стилей, сохраняя возможность локального прохода. Обычно он нужен после внешнего изменения условий измерения, которое не отражено в свойствах. Изменения текста, структуры, размеров и типографики в свойствах учитываются автоматически; одинаковый `layoutTemplate` не замораживает содержимое.

В компоненте внутри раскладки можно получить тот же механизм через контекст:

```tsx
import { useLayout } from '@dzenlotus/react-konva-layout';

const { invalidate, getLayout, getMetrics } = useLayout();

invalidate('node-1-description');
```

`useLayout()` предоставляет `invalidate`, `getLayout`, `getMetrics`; принудительный `remeasure` доступен через корневой ref. Методы пересчёта возвращают `void` и планируют работу на RAF после React commit. Немедленный `getLayout(id)` может вернуть предыдущие границы. Актуальные результаты доступны в `onLayout` и `onMeasure` после прохода; `getMetrics()?.scope` показывает `local`, `full` или `visual`.

## Собственные взаимодействия

Чтобы открыть свой редактор по двойному клику, передайте обработчик своему Konva `Text` либо обычный `onDblClick`/`onDblTap` ячейки. Библиотека только передаёт события; сама она не открывает редактор и не меняет текст. После сохранения собственного поля обновите `text` у `CellText` — пересчёт выполнится автоматически.

Пример textarea, позиционируемого поверх canvas, находится в [`src/examples/text-editor/EditableText.tsx`](../src/examples/text-editor/EditableText.tsx). Он принадлежит демо-приложению и не включён в библиотечный entry point. `ReferenceNode` передаёт в него свойства render-функции и собственный `onDescriptionChange`; редактор сохраняет значение через этот callback, а `CellText` автоматически измеряет обновлённый `text`.
