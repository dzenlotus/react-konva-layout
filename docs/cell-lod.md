# Выборочный LOD ячеек

С версии 0.5.0 библиотека не заменяет целую ноду при отдалении. Приложение решает, какое содержимое `Cell` и `CellText` рисовать, через два свойства:

| Свойство     | Поведение                                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| `renderWhen` | По умолчанию `true`: рисуется обычное содержимое ячейки. `false`: оно заменяется на `fallback`.                 |
| `fallback`   | ReactNode либо функция от измеренных границ. Без fallback содержимое скрывается, место в раскладке сохраняется. |

У `Cell` функция fallback получает `CellBounds`, как и обычная render-функция. У `CellText` она получает `CellTextRenderProps`: границы содержимого с учётом padding, текст и измеренные стили. Координаты локальны относительно группы ячейки. Fallback не участвует в HTML-измерении и не определяет размер ячейки.

`renderWhen={false}` заменяет собственную заливку, текст, пользовательскую отрисовку и вложенные элементы ячейки. Её Konva-группа, границы и обработчики остаются; для клика по пустой ячейке нужна собственная фигура с областью попадания. Если фон должен оставаться всегда, нарисуйте его в родительском `Flex` или в fallback. Скрытие родительской ячейки скрывает и её потомков независимо от их собственных условий.

## Условия принадлежат приложению

В библиотеке нет порогов масштаба. Используйте zoom своей камеры, выделение, состояние редактора или любое другое условие:

```tsx
import { memo } from 'react';
import { Image as KonvaImage, Rect, Text } from 'react-konva';
import { Cell, CellText, Flex } from '@dzenlotus/react-konva-layout';

const NodeContent = memo(function NodeContent({
  showPreview,
  showDescription,
  title,
  description,
  preview,
}: {
  showPreview: boolean;
  showDescription: boolean;
  title: string;
  description: string;
  preview: HTMLImageElement;
}) {
  return (
    <Flex width={320} direction="column" padding={16} gap={12} fill="white">
      <CellText text={title} fontSize={20} fontStyle="bold">
        {(props) => <Text {...props} />}
      </CellText>

      <Cell
        width="100%"
        height={156}
        renderWhen={showPreview}
        fallback={(bounds) => <Rect {...bounds} fill="#e4e9ed" cornerRadius={8} />}
      >
        {(bounds) => <KonvaImage {...bounds} image={preview} />}
      </Cell>

      <CellText text={description} fontSize={14} lineHeight={1.5} renderWhen={showDescription}>
        {(props) => <Text {...props} />}
      </CellText>
    </Flex>
  );
});
```

Заголовок здесь виден всегда. Фото заменяется прямоугольником, описание скрывается; их размеры и gap сохраняются. Выделение показывает детали даже при небольшом zoom. Числа 0,4 и 0,25 — политика этого компонента, не настройки движка.

В своём обработчике камеры обновляйте Konva-трансформацию и состояние, от которого зависит `renderWhen`. В компонент ноды передавайте готовые boolean-условия, как в примере восстановления камеры ниже. `memo` позволяет сохранить render-функции между пересечениями порогов, вместо перерисовки каждой ноды при каждом изменении zoom. Другие свойства ноды также должны сохранять ссылки, пока их данные не меняются.

Библиотека наблюдает внешнюю камеру для culling и плотности кешей; она не угадывает условия пользовательских ячеек. Если двигаете Stage императивно, одного `stage.scale(...)` недостаточно для изменения ваших boolean-свойств: обновите также состояние zoom или подпишитесь на свой store камеры. Условие может включать состояние редактирования: `renderWhen={showDescription || editing}` сохраняет смонтированным ваш редактор и его черновик при отдалении. Сам редактор принадлежит приложению.

`fallback` может быть обычным элементом либо функцией. Например, другой текст использует те же измеренные свойства:

```tsx
<CellText
  text={description}
  fontSize={14}
  renderWhen={showDescription}
  fallback={(props) => <Text {...props} text="…" />}
>
  {(props) => <Text {...props} />}
</CellText>
```

## Геометрия при переключении

HTML всегда описывает полную обычную раскладку: текст, стили, вложенные ячейки и ограничения размера. Изменение только `renderWhen` или `fallback` обновляет canvas и растровый кеш затронутой ноды. `onMeasure` не вызывается, границы измерительных HTML-элементов через `getBoundingClientRect` не читаются, размеры и положения соседей остаются прежними. `getMetrics()?.scope` при таком обновлении может быть `visual`; это публикация отрисовки с нулём измеренных элементов.

Если скрытое описание меняется, обновите `CellText.text`: оно измеряется обычным способом, даже пока не рисуется. При наличии безопасной независимой `layoutRoot` это локальный relayout ноды. Благодаря этому последующий показ описания использует актуальные границы. Если вместо `renderWhen` удалить сам `Cell` из React-дерева, изменится структура HTML и потребуется relayout.

Culling по viewport и растровые кеши работают вместе с выборочным LOD. `performance={{ enabled: false }}` отключает эти оптимизации, но не отменяет явно заданные `renderWhen` и `fallback`. `RenderMetrics.lodLevel` сообщает `full` либо `cell`, а `lodCells` — число видимых заменённых ячеек; эти метрики не задают условия и пороги.

## Загрузка сцены сразу при 10% или 5%

Камера восстанавливается приложением при создании Stage, например:

```tsx
import { useState } from 'react';
import { Layer, Stage } from 'react-konva';

const [view, setView] = useState(savedView);

<Stage
  width={viewportWidth}
  height={viewportHeight}
  x={view.x}
  y={view.y}
  scaleX={view.scale}
  scaleY={view.scale}
>
  <Layer>
    <NodeContent
      {...nodeProps}
      showPreview={selected || view.scale >= 0.4}
      showDescription={selected || view.scale >= 0.25}
    />
  </Layer>
</Stage>;
```

При сохранённом `scale: 0.05` порядок такой:

1. Stage сразу имеет масштаб 5%, а компоненты получают тот же zoom для условий `renderWhen`.
2. Первый HTML-проход измеряет полную раскладку в логических пикселях, независимо от масштаба Konva. Ячейка шириной 320 остаётся шириной 320 в модели и занимает 16 экранных пикселей при равномерном zoom 5%.
3. Первый canvas-кадр с готовой геометрией рисуется уже с нужными fallback. Библиотека не включает промежуточный zoom 1x и не рисует сначала полную детализацию.
4. Дальнейший zoom меняет canvas-содержимое, culling и плотность кешей; HTML повторно не измеряется. Если позднее загружается шрифт или меняются данные/ограничения, возможен отдельный необходимый relayout.

Если приложение сначала создаёт Stage с 1x, а сохранённую камеру загружает позже через effect, оно само допускает первый кадр при 1x. Инициализируйте камеру сохранённым значением или дождитесь его перед монтированием сцены.

Автоматическая плотность растровых кешей учитывает pixel ratio существующего Layer и полный внешний scale, включая родительские Group. Она не меняет логическую геометрию и не выбирает детализацию. При нехватке бюджета содержимое рисуется напрямую; библиотека не уменьшает разрешение вашего Layer.

При 5% в viewport может помещаться почти весь граф. Если оставить все ячейки включёнными, библиотека нарисует все видимые детали: culling не помогает против стоимости объектов, которые действительно видны. Для большой сцены задайте подходящие условия для фотографий, описаний, кнопок и декоративных фигур. Заголовки и порты можно сохранить всегда; их стоимость также входит в кадр.

В демо приложение выбирает отдельные правила: фото видно от 40% и ниже заменяется прямоугольником; описание видно от 25%; кнопки — от 15%; заголовок и порты остаются. Одинаковая политика действует в Optimized и Baseline. Прямые ссылки для проверки первого кадра: [`?stress=1&zoom=0.1`](http://localhost:4173/?stress=1&zoom=0.1) и [`?stress=1&zoom=0.05`](http://localhost:4173/?stress=1&zoom=0.05). Дополнительные `x` и `y` задают сохранённое смещение камеры.

Предыдущие [замеры 1000 нод](designed-stress.md) и [сравнение после рефакторинга](designed-stress-comparison.md) использовали автоматическую замену целых нод. Их результаты обзора нельзя переносить на новую политику ячеек: теперь объём работы определяет ваше содержимое и ваши условия.

## Что сохранять

Сохраняйте исходные данные графа отдельно от камеры: идентификаторы нод, текст, стили, ссылки или идентификаторы изображений, позиции нод и `view.x/y/scale`. При загрузке передайте эти данные компонентам и сразу восстановите камеру. Значения `renderWhen` вычисляются из восстановленного состояния приложения.

`stage.toJSON()` описывает фактически смонтированное Konva-дерево. При активном LOD там окажутся fallback, а скрытое обычное содержимое отсутствует; culling также исключает объекты вне viewport. Поэтому одного JSON Stage недостаточно для восстановления исходного полного графа. Внутренняя измеренная модель библиотеки хранит полную геометрию, но не заменяет данные приложения, React-компоненты, обработчики и загрузку изображений.

## Миграция с прежнего LOD

Удалены `performance.lodScale`, `lodLabel` и `onFocusRequest`. Перенесите свои условия в `Cell`/`CellText.renderWhen`, замену — в `fallback`, обработчики выбора и изменения камеры — в свой код. Без этих свойств все видимые ячейки рисуются полностью при любом масштабе.

## Проверка поведения

В production-сцене на 1000 нод проверены холодные загрузки при 5% и 10%. Первый draw сразу использовал соответственно scale 0,05 и 0,1. Геометрия всех 35 001 элементов совпала между масштабами; размер одной ноды оставался 360 × 429,78125 логических пикселей.

При переходах через zoom 0,1 / 0,2 / 0,3 / 0,5 / 1 / 1,6 / 0,05 чтений геометрии DOM и подключений измерительного HTML-root было 0. Ссылки дерева геометрии и Konva-группы проверяемой ноды сохранились. В Baseline первоначальный проход прочитал все 35 001 элементов, а три последующих переключения детализации были только `visual`, с нулём измерений.

Изменение настоящего текста скрытого описания выполнило локальное измерение 35 элементов. Собственный редактор демо сохранил черновик при zoom 5% через условие `showDescription || editing`; после сохранения и приближения отрисовался актуальный текст. Эти проверки подтверждают поведение, а не прежние FPS обзора.
