# Камера сцены

`usePanZoom` управляет трансформацией существующего `Stage`, `Layer` или `Group`. `useLayoutDrag` подключает перемещение камеры и ограничения области просмотра к тому же контроллеру. Оба хука работают с одной позицией и масштабом: после zoom проверяются те же границы, что и после drag.

Canvas, слои и состояние содержимого создаёт приложение. Перемещение камеры сохраняет логические размеры раскладки и не запускает HTML-измерение.

Пример с ограничениями доступен по `?camera=1`. Production-проверки React 19 и React 16.14.0: по 14 сценариев, включая native mouse/touch, pinch с продолжением одним пальцем, отключение управления во время жеста, сохранение позиции при обновлении опций и `reset`. В жестах не менялась ревизия измерения и не рендерился React-компонент примера. [Результаты](camera-verification.json) · [снимок](screenshots/camera-controls.png).

## Подключение

```tsx
import { useRef } from 'react';
import type Konva from 'konva';
import { Layer, Stage, Text } from 'react-konva';
import {
  CellText,
  Flex,
  Layout,
  useLayoutDrag,
  usePanZoom,
  type LayoutHandle,
} from '@dzenlotus/react-konva-layout';

export function Scene() {
  const stageRef = useRef<Konva.Stage | null>(null);
  const layoutRef = useRef<LayoutHandle | null>(null);

  const camera = usePanZoom({
    target: stageRef,
    initialView: { x: 40, y: 40, scale: 1 },
    minScale: 0.005,
    maxScale: 8,
  });

  useLayoutDrag({
    camera,
    bounds: () => layoutRef.current?.getLayout('content') ?? null,
    padding: 32,
    axis: 'both',
    panOn: 'background',
  });

  return (
    <>
      <button onClick={() => camera.zoomBy(1.2)}>Приблизить</button>
      <button onClick={() => camera.zoomBy(1 / 1.2)}>Отдалить</button>
      <button onClick={() => camera.reset()}>Сбросить камеру</button>
      <Stage ref={stageRef} width={900} height={600}>
        <Layer>
          <Layout
            ref={layoutRef}
            width={1600}
            height={1000}
            onLayout={() => camera.setView(camera.getView())}
          >
            <Flex id="content" width={1600} height={1000} padding={24}>
              <CellText text="Содержимое сцены" fontSize={24}>
                {(props) => <Text {...props} />}
              </CellText>
            </Flex>
          </Layout>
        </Layer>
      </Stage>
    </>
  );
}
```

Функция `bounds` читает актуальную геометрию после динамического изменения содержимого. В примере `onLayout` повторно применяет текущую камеру, чтобы проверить новые границы сразу после измерения. Пока функция возвращает `null`, ограничения области отсутствуют.

Оба хука принимают один объект опций. Начальная позиция и масштаб задаются один раз через `usePanZoom({ initialView: { x, y, scale } })`; `useLayoutDrag({ camera, ... })` использует эту же камеру. Новые объекты опций при ререндере не сбрасывают её позицию. Для последующего изменения используйте `setView`, для возврата к начальным значениям — `reset`; текущие ограничения продолжают действовать.

## `usePanZoom`

| Параметр               | Назначение                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| `target`               | Ref существующего Konva `Stage`, `Layer` или `Group`.                                                        |
| `initialView`          | Начальные `{ x, y, scale }`; можно передать сохранённую камеру.                                              |
| `minScale`, `maxScale` | Положительные границы равномерного масштаба; по умолчанию `0.005` и `8`. `0.03` означает 3%, `0.005` — 0,5%. |
| `wheelSpeed`           | Чувствительность масштаба к колесу.                                                                          |
| `enabled`              | Включение жестов камеры: wheel, pinch и pointer pan. Методы контроллера доступны при `false`.                |
| `onChange(view)`       | Получение актуальной камеры; уведомления объединяются через RAF.                                             |

Методы контроллера:

| Метод или свойство            | Назначение                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------------- |
| `getView()`                   | Текущие `{ x, y, scale }`.                                                              |
| `view.current`                | Readonly ref той же актуальной камеры.                                                  |
| `setView(view)`               | Применить позицию и масштаб с учётом действующих ограничений.                           |
| `zoomTo(scale, point?)`       | Установить масштаб вокруг указанной точки Stage; без точки используется центр viewport. |
| `zoomBy(factor, point?)`      | Умножить текущий масштаб на коэффициент.                                                |
| `panBy({ x, y })`             | Сдвинуть камеру на заданное число логических пикселей Stage.                            |
| `fitBounds(bounds, padding?)` | Вписать прямоугольник в viewport.                                                       |
| `reset()`                     | Вернуть начальную камеру с учётом текущих ограничений.                                  |

Колесо масштабирует вокруг указателя; два пальца выполняют pinch с переносом якоря. Один указатель перемещает камеру после подключения `useLayoutDrag`; пробел или средняя кнопка позволяют начать перемещение поверх содержимого. Поля ввода и кнопки внутри контейнера сохраняют свои события.

Контроллер сохраняет ссылку между рендерами. Трансформация применяется к native Konva и вызывает `batchDraw`; React state на каждом движении не создаётся. Для сохранения во внешний store используйте `onChange`, если обновление store необходимо во время жеста. Если UI должен показывать zoom, обновляйте небольшой компонент интерфейса, а не всё дерево содержимого.

Не задавайте параллельно устаревшие `x`, `y`, `scaleX`, `scaleY` в JSX управляемого объекта: React commit может перезаписать актуальную камеру. Восстанавливайте сохранённую камеру через `initialView` либо `setView`.

## `useLayoutDrag`

| Параметр  | Назначение                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `camera`  | Общий контроллер из `usePanZoom`, включая начальную позицию и масштаб.                                                                      |
| `bounds`  | `{ x, y, width, height }` в логических координатах содержимого до преобразования камеры; либо функция, возвращающая эти границы или `null`. |
| `padding` | Отступ области просмотра в логических пикселях Stage, независимо от DPR и zoom.                                                             |
| `axis`    | `'both'`, `'x'` или `'y'`: разрешённые направления drag и `panBy`; zoom и коррекция границ могут менять обе координаты.                     |
| `panOn`   | `'background'` для начала перемещения с фона; `'anywhere'` для начала на содержимом.                                                        |
| `enabled` | Включение перемещения одним указателем. Ограничения bounds продолжают действовать при `false`.                                              |

Для неограниченной сцены пропустите `bounds`. Для независимых корней с `Layout.placements` вычисляйте общий прямоугольник из позиций приложения и измеренных размеров: дерево измерения не включает координаты размещений.

На больших масштабах ограничения не позволяют увести viewport за края содержимого с учётом `padding`. Когда содержимое помещается целиком, оно центрируется по соответствующей оси. Поэтому zoom вокруг указателя может сместить якорь возле границы: итоговая камера обязана соблюдать ограничения.

Ограничения применяются к drag, программным изменениям, zoom и resize. Хуки используют общий контроллер, поэтому не накапливают независимые значения камеры. Внешнее изменение native трансформации тоже проходит через проверку.

## Координаты и существующие трансформации

Управляемый объект использует перенос и равномерный `scale`: один коэффициент для обеих осей, без собственного rotation, skew и offset. Трансформации его родителей могут быть другими. `x/y` относятся к его родителю. Точка `zoomTo/zoomBy` задаётся в координатах Stage до преобразования камеры; не передавайте непосредственно браузерные `clientX/clientY`.

При управлении вложенным `Group` или `Layer` преобразования родителей учитываются при вычислении якоря и границ. Передавайте границы содержимого в локальной системе управляемого объекта, до его camera-трансформации. Отдельный Stage для этого не нужен.

Масштаб 3%, 5% или 10% можно восстановить первым кадром через `initialView`. Ограничения `minScale/maxScale` должны включать сохранённое значение; иначе оно будет ограничено допустимым диапазоном. LOD остаётся условием приложения на `Cell.renderWhen` и `fallback`; камера не заменяет содержимое автоматически.

Наблюдение `Layout` за внешней трансформацией обновляет culling и плотность кешей без HTML-релейаута. Pixel ratio существующего Layer сохраняется. Изменение текста или состава ячеек отдельно запускает обычное локальное измерение: [обновление содержимого](content-updates.md).
