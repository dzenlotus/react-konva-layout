# Производительность и локальное редактирование — 0.2.0

Сравнение одной интерактивной сцены: 1000 независимых карточек, native Flex внутри, editable description, viewport canvas 1400 × 760, DPR 1. Baseline отключает оптимизации; Optimized сохраняет все 1000 карточек в модели, а на canvas монтирует видимые с запасом. Это новый fixture: исторические результаты старой Grid-сцены напрямую с ним не сравниваются.

Окружение: Apple M5, 10 CPU-ядер, 24 GB RAM, macOS 26.2, Headless Chrome 155 / ANGLE Metal. Production-сборка. Загрузка страницы/модулей/шрифтов и демонтаж предыдущей сцены исключены; новый монтаж React/HTML входит. Конец таймера — следующий RAF после полного `Layer.draw()` с scene и hit, не физический показ монитором.

| Показатель | Baseline | Optimized |
| --- | ---: | ---: |
| Монтаж → готовый кадр, медиана 3 прогонов | 3454 мс | **1537,6 мс** |
| Диапазон этих прогонов | 1726,7–4334,4 мс | **766,2–1738,2 мс** |
| Draw первого кадра, медиана | 782,1 мс | **7,7 мс** |
| Объектов Konva в обычном viewport | 52 001 | **819** |
| Чтений геометрии при первом layout | 25 001 | **1025** |
| Повторно использованных шаблонов | 0 | **999** |

Первый монтаж в этой небольшой серии ускорился примерно в **2,25 раза**. Разброс заметный; исходные данные сохранены, это не обещание фиксированной задержки на любой машине.

## Редактирование и камера

- Description: **25 чтений геометрии**, только `stress-node-0000-card`. Локальный замер: **2,2–8,7 мс**, медиана **5,2 мс**. Сохранение → следующий кадр: **50–53,8 мс**.
- Длинное описание увеличило высоту своей ноды с 284 до 781,39 px. Соседняя группа Konva и её raster cache сохранили те же объекты.
- Перемещение камеры внутри закешированной области: draw **0,5 мс**; при первом входе в новую область **4,6 мс** в контрольных пробах. В обоих случаях HTML layout не вызывался.
- При Resize всех 1000 карточек: **1395,8–1663,1 мс**, один общий проход вместо двух. Первичное создание HTML и массовое изменение размеров остаются дорогими операциями.
- В покое в документе **0 измерительных HTML-узлов**. HTML textarea появляется только при редактировании и удаляется после закрытия. Само отсоединённое portal-дерево остаётся в памяти.

## CPU slowdown 4×

Это эмуляция CPU на той же машине с тем же M5 GPU, а не реальный слабый компьютер. Для холодного монтажа выполнена одна пара, поэтому она показывается как отдельная проба:

| Операция | Baseline | Optimized |
| --- | ---: | ---: |
| Монтаж → кадр | 21 169,2 мс | **3464,2 мс** |
| Локальный HTML relayout | — | **18,3 мс / 25 элементов** |
| Сохранение description → кадр | — | **140,2 мс** |
| Draw при входе в новую область | — | **34,8 мс** |
| Draw следующего движения в закешированной области | — | **2 мс** |

Вход в новую область требует создания и кеширования новых видимых нод, поэтому он заметно дороже повторного движения. Постоянные 60 FPS на любом устройстве этот замер не гарантирует.

## Дальний общий вид

При масштабе ниже `.3` используется LOD с упрощёнными карточками и подписями. Ниже `.12` остаются силуэты, которые рисуются одним custom Shape на последовательную группу одинаковых стилей. Для одноцветного fixture это **1000 пустых metadata Groups + 1 Shape**, без огромного bitmap мира и без raster cache. Metadata Groups сохраняют id/геометрию; обработчик общей фигуры определяет ноду под указателем и поддерживает click/double-click/double-tap для возврата к деталям.

Контрольные полные draw: **2,3–4 мс** без slowdown и **8,6–13,4 мс** при CPU 4×. Все 1000 силуэтов участвуют в отрисовке. Камера и переход LOD не запускают HTML relayout.

## Реализованные изменения

- Компактное дерево рисования вместо Group на каждый Row/Col/spacer; полное дерево layout сохраняется.
- Viewport culling с overscan, pan/zoom к курсору, pointer/touch gestures, уровни детализации и пакетное рисование силуэтов.
- Кеш только видимых сложных нод, бюджет 32 MiB, освобождение при уходе/изменении; декоративные фигуры не участвуют в hit-testing.
- Typed comparison, стабильные ссылки на неизменные SceneNode, отсутствие JSON-сериализации полного дерева в горячем пути.
- Независимые `layoutRoot`, dirty boundaries, контекст `useLayout()` и явное `invalidate(id)` / `remeasure(id)`.
- Ограниченный кеш шаблонов и вычисленных стилей, компактные collision-free идентификаторы, устранение повторного resize-прохода.
- Native textarea с правильным transform, автофокусом, многострочным вводом, IME, сохранением через blur/Cmd+Enter и отменой через Escape. Пустой editable field имеет полную hit-область.

В обычном Flex/Grid потоке изменение размеров ноды может сдвинуть соседей; при таких зависимостях и небезопасном CSS используется полный корректный пересчёт. Полное первое HTML-дерево всё ещё создаётся: оптимизация сокращает чтения размеров и canvas-объекты, а не отменяет этот этап.

## Воспроизведение

`npm run build` → `npm run preview` → `http://localhost:4173/?stress=1`. Выберите Baseline или Optimized и выполните новый монтаж. Из DevTools доступны `layoutStress.run(mode)`, `resize()`, `edit(text)`, `view({x,y,scale})`, `overview(true)` и `stats()`. CPU slowdown задаётся в DevTools отдельно.

Проверены logical double-click/tap по id ноды (A→B без zoom, A→B→B с zoom, фон сбрасывает пару), native mouse double-click, touch double-tap, сохранение/отмена/IME, редактор при zoom и CSS scale, сохранение редактора при загрузке шрифтов, локальный рост ноды, неизменность соседнего кеша, camera без layout, debug-границы при zoom и независимое ревью. Unit-тесты не добавлялись.
