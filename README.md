# react-konva-layout

Flex/Grid раскладка для существующей сцены React Konva. Браузер измеряет временное HTML-дерево, затем библиотека переносит границы в Konva-группы. Фигуры рисует ваш код.

```tsx
import { Stage, Layer, Rect, Text } from 'react-konva';
import { Flex, Cell, CellText } from '@dzenlotus/react-konva-layout';

<Stage width={900} height={600} {...yourCamera}>
  <Layer>
    <YourExistingShapes />
    <Flex width={600} padding={20} gap={16} alignItems="center">
      <Cell width={120} height={100}>
        {(bounds) => <Rect {...bounds} fill="#dce8cf" cornerRadius={12} />}
      </Cell>
      <Cell flexGrow={1} minWidth={0}>
        <Flex direction="column" gap={8}>
          <CellText text="Image transform" fontSize={20} fontStyle="bold">
            {(textProps) => <Text {...textProps} />}
          </CellText>
          <CellText text={description} fontSize={14} lineHeight={1.5}>
            {(textProps) => <Text {...textProps} />}
          </CellText>
        </Flex>
      </Cell>
    </Flex>
  </Layer>
</Stage>;
```

`Flex` и `Cell` становятся группами с сохранением вложенности. `Cell` принимает вложенную раскладку либо функцию `{ x, y, width, height } => ReactNode`. Координаты функции локальны относительно группы ячейки: `x = 0`, `y = 0`. Поэтому смещение группы не применяется к фигуре дважды.

`CellText` измеряет прозрачный HTML-текст с заданными стилями и переносами. Функция получает размеры содержимого и готовые свойства Konva `Text`: `text`, `fontSize`, `fontFamily`, `fontStyle`, `lineHeight`, `fill`, `align`, `wrap` и другие измеренные параметры. Передавайте их через `<Text {...textProps} />`, чтобы HTML и canvas использовали один источник текста и стилей. С `padding` координаты смещаются внутрь ячейки, а размеры уменьшаются на отступы.

Поддержаны также `fontWeight`, `fontVariant`, `letterSpacing`, `verticalAlign`, `textDecoration`, `underlineOffset`, `ellipsis` и `direction`. Вес и курсив объединяются в native `fontStyle`, например `italic 600`; CSS-переопределения учитываются при измерении. [Типографика, пример и границы соответствия HTML/Konva](docs/text-typography.md). Сравнение доступно по `?text=1`.

`CellText` отвечает только за измерение и передачу свойств. Изменение `text`, стилей или ограничений размера автоматически планирует новый layout; источник изменения может быть любым — ваш input, store, API или другой компонент. Обработчики событий и интерфейс редактирования принадлежат приложению.

HTML полностью отсоединяется от документа после измерения. React-состояние сохраняется в отсоединённом DOM-дереве. При обновлении размеров/текста HTML временно возвращается для нового измерения. `debug` включает видимую HTML-разметку с `data-testid` поверх canvas; выключение снова удаляет её из документа.

## Подключение

Публичный репозиторий: [dzenlotus/react-konva-layout](https://github.com/dzenlotus/react-konva-layout). Пакет пока не опубликован в npm.

```sh
npm install github:dzenlotus/react-konva-layout
```

Нужны peer dependencies React/ReactDOM 19, react-konva 19 и Konva 10. Точные диапазоны указаны в `package.json`. GitHub-установка запускает `prepare` и собирает ESM + TypeScript declarations в `dist-lib/`.

Для React/ReactDOM 16.14.0, react-konva 16.13.0-6 и Konva 8.4.3 подготовлена отдельная сборка: [установка с корневым npm override и обязательными aliases Konva](docs/react16.md). Контексты можно передать через `Layout.contexts` или `contexts` самостоятельного корневого `Flex`.

Для разработки:

```sh
npm install
npm run dev
npm run build
npm run format:check
```

Основной пример показывает встраивание в существующий `Stage/Layer`. `?scene=1` — свободная сцена: карточки в разных позициях и порядке, выделение и drag. `?stress=1` — отдельная сетка из 1000 карточек `ReferenceCard` с фотографией, текстом, портами и кнопками; доступны замеры монтажа, pan/zoom FPS и выборочный LOD ячеек. `?playground=1` — дополнительные примеры Flex/Grid. Приложение создаёт canvas и владеет камерой; для её управления можно подключить библиотечные `usePanZoom` и `useLayoutDrag`.

## Готовая карточка

[ReferenceCard.tsx](src/examples/ReferenceCard.tsx) — оформленная карточка обработки изображения через Flex/Cell/CellText: заголовки, фотография в превью, три входных и три выходных порта, редактируемое описание, кнопки запуска и настроек. Иерархия взята из примера CodeSandbox; размеры текстовых блоков определяет их содержимое.

Компонент размещается внутри существующего Group/Layer и не создаёт Stage или камеру:

```tsx
<Group x={300} y={84}>
  <ReferenceCard
    id="element-1"
    width={360}
    previewImage={loadedImage}
    description={description}
    onDescriptionChange={setDescription}
    onAction={(action) => console.log(action)}
    onPortSelect={(side, index) => console.log(side, index)}
  />
</Group>
```

`previewImage` — загруженный `HTMLImageElement`; компонент вписывает его в область превью с обрезкой по центру. Загрузка изображения находится в приложении: пример использует локальный JPEG. Изменение изображения обновляет отрисовку и растровый кеш. Демо добавляет редактирование описания двойным кликом собственным редактором из `src/examples/text-editor/`; библиотека не создаёт textarea и не назначает действие на двойной клик. Сохранённый текст передаётся в `CellText` через `text`, после чего пересчитывается эта карточка.

## API

В версии 0.6.0 появился `Layout.placements`: независимые карточки используют один движок измерения, а приложение отдельно задаёт их позиции, порядок наложения и обработчики Konva. Перемещение карточки не меняет её HTML-раскладку. [Пример общего Layout с drag и внешним состоянием](docs/element-positioning.md).

В версии 0.5.0 удалена автоматическая замена целой карточки при отдалении. У `Cell` и `CellText` появились `renderWhen` и `fallback`; пороги и условия определяет приложение. Подробности: [выборочный LOD и загрузка сцены при 5%/10%](docs/cell-lod.md).

В версии 0.4.0 из библиотечного API удалены `editable`, `onTextChange`, `onEditStart` и `onEditEnd`. `CellText` только измеряет переданные данные; редакторы и их события находятся в коде приложения.

| Компонент                                 | Назначение                                                                                                                                                  |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Flex`                                    | Корневая или вложенная Flex-раскладка. `direction="row"` по умолчанию, либо `"column"`.                                                                     |
| `Cell`                                    | Ячейка-группа с вложенной раскладкой либо функцией от измеренных границ.                                                                                    |
| `CellText`                                | Ячейка-группа с измерением текста и функцией от готовых свойств `Text`.                                                                                     |
| `Layout`                                  | Общий корень измерения. Принимает логические `width/height`, `x/y`, `placements`, `debug`, `performance` и события. Можно поместить в существующий `Group`. |
| `Grid`, `Row`, `Col`, `Box`, `LayoutText` | Дополнительные примитивы из первого прототипа. Основной API — `Flex/Cell/CellText`.                                                                         |

Параметры раскладки: `width`, `height`, `minWidth`, `maxWidth`, `minHeight`, `maxHeight`, `padding`, `gap`, `columnGap`, `rowGap`, `alignItems`, `justifyContent`, `alignSelf`, `flexGrow`, `flexShrink`, `flexBasis`, `flexWrap`. Дополнительные CSS-ограничения можно передать через `style`. Числа — логические CSS-пиксели; допускаются проценты. Для CSS Grid доступны `gridTemplateColumns/gridTemplateRows`.

У `CellText` есть `text`, `fontSize`, `fontFamily`, `fontStyle`, `lineHeight`, `color`, `align`, `wrap`. `lineHeight` — множитель размера шрифта. Шрифт и переносы участвуют в измерении; итоговые свойства передаются вашей функции.

Корневой `Flex` или `Layout` предоставляет `ref: LayoutHandle`:

- `getGroup()` / `getStage()` — доступ к существующим Konva-объектам;
- `getLayout(id)` / `getMetrics()` — сохранённая геометрия и метрики;
- `invalidate(id?)` — запланировать измерение ближайшей `layoutRoot`, используя доступные шаблоны геометрии; без `id` — сбросить кеши измерения и пересчитать всё дерево;
- `remeasure(id?)` — сбросить кеши шаблонов и вычисленных стилей, затем запланировать измерение ближайшей `layoutRoot`; без `id` — всего дерева.

`useLayout()` внутри раскладки предоставляет `invalidate/getLayout/getMetrics`. Запросы объединяются через RAF; методы не возвращают новые границы синхронно. `onLayout` получает обновлённое дерево координат, `onMeasure` — область и стоимость измерения, `onRenderStats` — количество видимых корней, фигур и объём кешей. Одинаковые метрики повторно не отправляются; при замене callback он получает текущий снимок. Без подписчика статистика не собирается.

## Камера сцены

`usePanZoom` управляет существующим `Stage`, `Layer` или `Group`. `useLayoutDrag` перемещает ту же камеру и ограничивает область просмотра. Zoom, drag, программное изменение камеры и resize соблюдают общие ограничения.

```tsx
const camera = usePanZoom({
  target: stageRef,
  initialView: { x: 40, y: 60, scale: 0.5 },
  minScale: 0.005,
  maxScale: 8,
});

useLayoutDrag({
  camera,
  bounds: () => layoutRef.current?.getLayout('content') ?? null,
  padding: 32,
  panOn: 'background',
  axis: 'both',
});

// Кнопки и внешний store используют тот же контроллер.
const zoomIn = () => camera.zoomBy(1.2);
const moveRight = () => camera.panBy({ x: 100, y: 0 });
```

Хуки изменяют native трансформацию через `batchDraw`, без React state на каждом кадре и без HTML-релейаута. Stage/Layer и состояние содержимого остаются у приложения. Пример подключения, системы координат, сохранение камеры и все параметры: [управление камерой сцены](docs/camera-controls.md).

## Внешние pan/zoom и обновления содержимого

Сценой, слоями и камерой владеет приложение. Библиотека наблюдает трансформации существующих `Stage`, `Layer` и родительских `Group`, включая поворот, skew и неодинаковый scale. Pan/zoom обновляет culling и плотность кешей без повторного HTML-измерения. Условия LOD ячеек приложение передаёт через `renderWhen`; изменение только этого свойства или `fallback` обновляет canvas с сохранением измеренных границ. Обработчики управления камерой подключаются по выбору через `usePanZoom/useLayoutDrag`; существующую камеру приложения также можно сохранить. Pixel ratio вашего Layer не меняется.

Передавайте актуальные данные в свойства раскладки. Обычное изменение `text`, `fontSize`, `fontFamily`, `lineHeight`, `wrap`, `width` или `style` не требует ручного вызова `invalidate`.

Пометьте независимую карточку `layoutRoot`, чтобы её текст пересчитывал только эту карточку:

```tsx
<Flex
  id="element-1"
  layoutRoot
  width={260}
  direction="column"
  gap={12}
  style={{ position: 'absolute', left: 40, top: 60 }}
>
  <CellText id="description" text={description} fontSize={14}>
    {(textProps) => <Text {...textProps} />}
  </CellText>
</Flex>
```

После `setDescription(nextText)` или обновления вашего store ближайшая `layoutRoot` измеряется автоматически. Абсолютная карточка с заданной шириной может менять высоту независимо. Вложенный блок, например список actions, тоже можно пометить `layoutRoot`: добавление, удаление и перестановка измеряют только его поддерево. Если блок в обычном потоке меняет внешний размер, пересчёт поднимается к ближайшей родительской границе, чтобы обновить зависимые позиции. Без безопасной родительской границы, при структурных CSS-селекторах или недоступных таблицах стилей может потребоваться полный проход.

Для внешнего изменения, которое не отражается в свойствах, можно явно запросить `layoutRef.current?.remeasure('description')` или `useLayout().invalidate('description')`. Изменение `Konva.Text` напрямую не меняет HTML-модель: обновите также `text`/стили у `CellText`. У произвольных фигур размеры задаются через `Cell`; библиотека не определяет их по содержимому render-функции.

[Обновление содержимого, динамические списки и ручная инвалидация](docs/content-updates.md). В `?scene=1` выберите карточку и меняйте её actions кнопками над canvas; остальные карточки сохраняют свои позиции.

[Позиции карточек, выделение, drag и локальные координаты](docs/element-positioning.md). Для множества свободных элементов используйте один общий `Layout` с `placements`: измеряемые корни остаются на `(0, 0)`, а позиции и порядок их canvas-групп принадлежат приложению.

```tsx
<Layout width={1200} height={800} placements={placements}>
  {cardModels.map((element) => (
    <Flex
      key={element.id}
      id={element.id}
      layoutRoot
      width={300}
      style={{ position: 'absolute', left: 0, top: 0 }}
    >
      <CellText text={element.description} fontSize={14}>
        {(textProps) => <Text {...textProps} />}
      </CellText>
    </Flex>
  ))}
</Layout>
```

Элемент `placements` содержит `id` независимого корня, `x/y`, `draggable` и обработчики `onClick/onTap/onDragStart/onDragMove/onDragEnd`; доступен `dragBoundFunc`. Массив задаёт порядок от заднего плана к переднему. В `onDragEnd` сохраняйте `event.currentTarget.position()` в своё состояние. Не переносите карточки через CSS `left/top` и не переставляйте измеряемые `children`, если нужно изменить только положение или порядок canvas. Сохраняйте ссылки на неизменённое дерево компонентов, чтобы обновление позиции не пересоздавало содержимое остальных карточек. Полный пример находится в документе выше.

Размещение использует существующую корневую Konva-группу карточки: дополнительной внешней группы нет. `event.currentTarget.id()` совпадает с `placement.id`, границы дочерних ячеек остаются локальными. Интерактивному корню добавляется область попадания по его измеренным границам без рисования дополнительного прямоугольника на scene canvas.

В свободном демо приложение временно переносит перетаскиваемый корень в собственный второй `Layer`: при drag перерисовывается только он, остальные карточки остаются на первом слое. Перед записью позиции и порядка корень возвращается в родителя React. Во время pan/zoom камера обновляется через native Stage, а React обновляет только изменившиеся условия LOD ячеек. Схема интеграции и ограничения переноса между слоями описаны в [документе о размещении](docs/element-positioning.md#drag-на-отдельном-слое).

## Оптимизации

```tsx
<Flex
  performance={{
    cull: true,
    overscan: 144,
    cache: true,
    cacheBudgetMB: 32,
    cachePixelRatio: 'auto', // плотность существующего Layer × масштаб
  }}
>
  {children}
</Flex>
```

По умолчанию `cachePixelRatio="auto"`: плотность растрового кеша учитывает фактический pixel ratio существующего Layer и масштаб всех родительских трансформаций. При переходе между уровнями плотности обновляются только видимые кеши; pan не пересоздаёт их и не запускает HTML layout. Если нужный кеш превышает бюджет, карточка рисуется напрямую. Числовое значение фиксирует плотность для явно выбранного режима качества, например benchmark с DPR1.

Плотность кеша меняется по степеням двойки с гистерезисом и нижней границей `1/64`. Это позволяет кешировать маленькие карточки при overview, сохраняя разрешение самого Layer. Плотность hit-кеша равна `min(1, scenePixelRatio)`. Бюджет учитывает scene- и hit-поверхности; дополнительная filter-поверхность резервируется только для групп с настроенными фильтрами. По умолчанию бюджет равен 32 MiB. Количество native групп и фигур пересчитывается при изменении структуры, а не на каждом движении камеры.

Playground и `?stress=1` наследуют разрешение устройства и используют автоматическую плотность кеша. Дополнительный параметр `retina=1` больше не нужен. [Замеры 1000 оформленных карточек при DPR2 и замедлении CPU](docs/designed-stress.md) · [Диагностика чёткости и снимки до/после](docs/embedded-layout.md#чёткость-на-retina-и-при-zoom).

[Стресс-тест свободной сцены и сравнение с сеткой](docs/free-scene-stress.md) использует `?scene=1&benchmark=1` с фиксированным Stage 1400 × 760. Через `window.freeScene.benchmark.mount` можно выбрать свободное или сеточное размещение одинаковых карточек, а через `interact` — измерить drag, pan и zoom. Это инструменты демо; в библиотечный пакет они не входят.

[Сравнение React 16.14.0 и React 19](docs/react16-vs-react19-stress.md): одна сцена из 1000 свободных элементов, DPR 2, drag на 3%, pan/zoom и CPU ×4/×6. Для React 16 общий пример собирается командой `npm run build:react16-stress`; результаты и исходные данные сохранены отдельно от прежних замеров.

Сохранены coalescing через RAF, стабильные ссылки неизменённых ветвей, локальные измерения, кеши видимых карточек с ограничением памяти и culling. `layoutTemplate="card-v1"` явно включает повторное использование геометрии одинаковых карточек; подпись учитывает структуру, текст, ограничения, шрифты и CSS-контекст. `cache={false}` отключает растровый кеш конкретной карточки. `performance={{ enabled: false }}` отключает оптимизации измерения, culling и растровое кеширование для сравнения. Явно переданные `renderWhen` и `fallback` действуют в обоих режимах.

`Flex/Cell/CellText` сохраняют группы. Компактная отрисовка может убирать вспомогательные группы старых примитивов. Библиотека не заменяет карточку целиком и не назначает пороги масштаба. У `Cell`/`CellText` `renderWhen={false}` заменяет только содержимое этой ячейки на `fallback` или скрывает его, если fallback не задан. Размеры, отступы, gap и положения соседей сохраняются. Порты, кнопки и тексты можно управлять независимо; взаимодействиями и камерой владеет приложение.

Полная модель остаётся доступна через `getLayout`, даже если canvas-объекты вне viewport не смонтированы. Для произвольных фигур, выходящих далеко за границы ячейки, задайте достаточный `overscan` или отключите culling.

Замеры ниже относятся к прежнему встроенному LOD целых карточек; их FPS при отдалении не описывает произвольную политику `renderWhen` версии 0.5.0.
